# What happens to a tool call when the safety hook misbehaves

The hook was asked about `rm -rf build` and answered in ten different ways. "Runs" means the
agent goes ahead with the command. Every outcome comes from the agent's own code (see the
README for how), at a pinned commit. Generated by `study/hook-failures/render.ts`; CI fails if
this file no longer matches.

| The hook... | Gemini CLI | Codex |
| --- | --- | --- |
| a well-formed deny with a reason (the control) | blocked | blocked |
| asks for the user's confirmation | asks the user | **runs** |
| explicitly allows the call | **runs** | **runs** |
| prints nothing and exits 0 (no opinion) | **runs** | **runs** |
| crashes: exits 1 and prints nothing | **runs** | **runs** |
| exits 2 with a reason on stderr | blocked | blocked |
| exits 2 with nothing on stderr | **runs** | **runs** |
| prints JSON that doesn't parse | **runs** | **runs** |
| a deny that also sets a field the agent doesn't support for this event | blocked | **runs** |
| hangs past its timeout | **runs** | **runs** |

Outside "allow" and "no opinion", the command still runs in these cases:

- Gemini CLI: crash, exit2-silent, bad-json, timeout
- Codex: ask, crash, exit2-silent, bad-json, deny-extra-field, timeout
